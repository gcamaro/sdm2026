CAPÍTULO 10 · M · Model

A equipe ajusta os primeiros modelos

Algoritmos são maneiras diferentes de representar associações, com escolhas de complexidade.

Base no curso: slides 256–307; 322–333.

No caderno da equipe

Cada integrante prefere um algoritmo. O grupo decide comparar mecanismos e limites antes de escolher um vencedor. A regra passa a ser: usar o mesmo problema bem definido e compreender o que cada configuração permite aprender.

Uma visão básica das famílias

AlgoritmoIdeia em linguagem simplesAjuste que merece atenção
BIOCLIM / DOMAINEnvelope de condições ou similaridade com as ocorrências.Sensibilidade a extremos e à representação ambiental; presentes na teoria do curso.
Maxent · MAXContrasta presenças com ambientes disponíveis e estima uma superfície relativa.Classes de funções e regularização.
Random Forest · RAFCombina várias árvores ajustadas a amostras e subconjuntos de preditores.Complexidade das árvores e variáveis candidatas.
GBMAcrescenta árvores para corrigir erros do conjunto anterior.Número de árvores, taxa de aprendizado e profundidade.
NETCombina entradas em uma rede de unidades ajustáveis.Arquitetura e regularização.
SVMUsa uma fronteira e funções kernel para separar padrões.Custo e parâmetros do kernel.
GAURepresenta relações por uma função com estrutura de covariância.Covariância e complexidade efetiva.
GLMRepresenta uma resposta por uma combinação parametrizada dos preditores.Termos, interações e relação entre amostra e parâmetros.
GAMUsa funções suaves para representar respostas não lineares.Flexibilidade dos suavizadores.

O workflow SDM usa MAX, RAF, GBM, GAU, NET, SVM, GLM e GAM, com condições para alguns ajustes. BIOCLIM e DOMAIN fazem parte da discussão teórica dos slides, mas não compõem esse ensemble de oito algoritmos. Não existe obrigação de ajustar todas as famílias em todo estudo.

Configuração do roteiro

sample.size        <- nrow(presence.points.model)    # Tamanho da amostra
models.threshold   <- "max_sens_spec"                # Limiar de corte dos algoritmos
models.metric      <- "SORENSEN"                     # Métrica para seleção de modelos
ensemble.method    <- "median"                       # Método de ensemble
ensemble.threshold <- "SORENSEN_mean"                # Limiar para seleção dos modelos para o ensemble
ensemble.cut       <- 0.60                           # Valor do limiar de corte para compor o ensemble

# Predictors
predictors.names <- names(predictors.model)

Limiar, métrica e regra de composição do ensemble.
Antes de executar: Objetos do fluxo preparados. SORENSEN é a métrica configurada para seleção e 0,60 é um critério do roteiro, não um limite universal de qualidade.

R · trecho original · linhas 2032–2067
# MAX
# Definição das feature classes com base no tamanho da amostra
# Classes
if (sample.size < 10) {
  classes <- "l"
} else if (sample.size < 15) {
  classes <- c("l", "lq")
} else {
  classes <- c("l", "h", "lq", "lqh")
}

# Sample size
if (sample.size < 20) {
  regmult.values <- seq(1, 5, 1)
} else {
  regmult.values <- seq(0.5, 5, 0.5)
}

tune.grid.max <- expand.grid(
  regmult = regmult.values,
  classes = classes
)

max.fit.model <- tune_max(
  data = data.model,
  response = "pr_ab",
  predictors = predictors.names,
  background = background.points.model,
  partition = ".part",
  grid = tune.grid.max,
  thr = models.threshold,        
  metric = models.metric,         
  clamp = TRUE,
  pred_type = "cloglog",
  n_cores = max(1L, parallel::detectCores() - 2L, na.rm = TRUE)
)

O Maxent usa classes e multiplicadores de regularização definidos em função do tamanho amostral.
Antes de executar: sample.size, data.model, background.points.model, predictors.names e colunas de partição já disponíveis; flexsdm carregado.
Fonte: Zaprionus tuberculatus SDM e Futuro 2026-10-12.R.

Menos complexidade pode perder padrões relevantes; mais complexidade pode aprender particularidades da amostra. O ajuste de hiperparâmetros procura uma solução dentro de um conjunto de candidatos. Não elimina problemas de amostragem, escalas incompatíveis ou falhas da avaliação.

A saída não garante probabilidade

Mesmo uma saída entre zero e um, incluindo cloglog, precisa de pressupostos e calibração para ser interpretada como probabilidade de ocorrência. No livro, a leitura adotada é adequabilidade.

O que registrar

  • Versão do pacote e algoritmo efetivamente ajustado.
  • Grade de parâmetros, critério de escolha e partições utilizadas.
  • Modelos que falharam, foram descartados ou não atenderam às condições da amostra.
  • Tempo e recursos relevantes para repetir o procedimento.
